# Experimental Methodology — How Results Were Derived

This document traces each finding in `PTA_Limitations_and_Patch_Signal_Analysis.md` back to its source: the script that produced it, the data it consumed, and the exact output file containing the numbers.

---

## Part 1: PTA's Prototype Drift Problem

### 1.1 Tie-Breaking Analysis

**Question**: When CLIP and the image-level prototype disagree, how often is each correct?

**Script**: `scripts/analyze_ties.py`

**Input**: Per-sample JSONL records from `outputs/records_patch_benefit/` (canonical arm `PatchModPTA-CS`). Each record contains `logits.clip`, `logits.image_proto`, and `target`.

**Method**:
- Define "tie" as `clip.argmax != image_proto.argmax` (component disagreement)
- For each dataset, compute:
  - Total samples, tie count, tie rate
  - PTA accuracy on tie samples
  - PatchModPTA accuracy on tie samples
  - Accuracy delta on ties
  - Breakdown: patch helps (patch correct, global wrong) vs hurts (patch wrong, global correct)

**Output**: `outputs/tie_breaking_analysis.md`

**Scope**: dtd only, seed 1. (Other datasets not analyzed for this specific question.)

**Key finding**: PTA accuracy when CLIP and image_proto disagree: 12.9% (dtd). Image-level prototype is wrong 75.3% of the time in these cases, but no confidence-based filter can catch this.

---

### 1.2 Image-Level Prototype Drift

**Question**: Does the image-level prototype drift when CLIP is confidently wrong?

**Script**: No dedicated script. This finding was derived from consolidated manual analysis across multiple experiments.

**Source**: `outputs/patch_level_fusion_summary.md` (Section: "Why PTA Fails"), which synthesized results from:
- `scripts/analyze_records.py` — computed per-method accuracy tables
- `outputs/experiment_summary.md` — 5×5×5 grid results

**Method**: Cross-referencing accuracy patterns with prototype behavior observed across the full experimental suite.

**Key finding**: When CLIP is confidently wrong, the image-level prototype adapts to the wrong class, locking in the error.

## Part 2: Why Patch-Level Prototypes Don't Fix PTA

### 2.1 Bank Quality: Purity

**Question**: What fraction of written patches actually belong to the claimed class?

**Script**: `scripts/analyze_prototype_purity.py`

**Input**: Stored zero-shot CLIP scores and true labels from `outputs/records_patch_benefit/` (canonical arm `PatchModPTA-CS`).

**Write-time settings**:
- Confidence source: text embeddings (`conf_source="text"`)
- Confidence threshold: 0.3 (`conf_threshold=0.3`)
- Multi-gate: writes to multiple class banks when confidence exceeds threshold

**Method**: Replay the `multi_gate` write mask from stored data. No new GPU runs. Computes:
- Overall purity (fraction of all writes correct)
- Primary-write purity (writes to predicted class)
- Collateral-write purity (writes to other classes triggered by same image)
- Collateral share (fraction of all writes that are collateral)

**Output**: `outputs/prototype_purity_report.md`

**Datasets**: dtd, oxford_flowers, oxford_pets (4 seeds each)

---

### 2.2 Bank Quality: Separability

**Question**: Even with a pure bank, do clusters from different classes look similar?

**Scripts**: 
- `scripts/analyze_prototype_separability.py` — cosine similarity between cluster centers
- `scripts/analyze_prototype_separability_v2.py` — variance-aware scoring (uses both center and spread)

**Input**: Final per-class Gaussian bank dumps from `outputs/patch_bank_dumps/` (loaded via `DUMP_PATCH_BANK` env var in `models/patch_modulated_pta.py`).

**Method**: For each dataset, measure:
- Intra-class coherence (how similar a class's own patches are)
- Nearest cross-class confusability (how similar they are to the most similar other class)
- Separability margin (intra minus cross; negative = classes overlap)

**Output**: 
- `outputs/prototype_separability_report.md` (cosine-only)
- `outputs/prototype_separability_v2_report.md` (variance-aware)

**Datasets**: dtd, oxford_flowers, oxford_pets (seed 1 only)

---

### 2.3 The Structural Asymmetry

**Question**: Why does patch fusion help on dtd but hurt on oxford_pets?

**Script**: No dedicated script. This is a synthesis of findings from Parts 2.1 and 2.2 combined with baseline accuracy data.

**Source data**:
- Baseline accuracy from `outputs/experiment_summary.md` (generated by `scripts/run_experiments.sh`)
- Purity/separability from sections 2.1 and 2.2

**Method**: Cross-referencing bank quality metrics with baseline accuracy and observed fusion performance.

**Key finding**: Adding a noisy signal to a high-accuracy baseline (oxford_pets, 91%) breaks more correct answers than it fixes. Adding the same signal to a low-accuracy baseline (dtd, 47.5%) can help slightly.

## Part 3: Patch Agreement as Quality Signal

### 3.1 The Agreement Signal

**Question**: Does agreement between CLIP's CLS-level guess and the patch-level vote predict correctness?

**Script**: `scripts/validate_patch_vote_signal.py`

**Input**: Per-sample records from `outputs/records_patch_benefit/`

**Method**:
- Compute patch-to-text zero-shot classification (independent of any bank state)
- Compare patch vote argmax to CLIP argmax
- For agree/disagree subsets, compute CLIP accuracy

**Output**: `outputs/patch_vote_validation_report.md`

**Datasets**: dtd, oxford_flowers, oxford_pets (4 seeds each)

**Key finding**: When CLIP and patch vote agree, CLIP is much more likely to be correct (30+ pp purity gap).

---

### 3.2 Aggregation Methods

**Question**: Which pooling method produces the strongest patch-level signal?

**Script**: `scripts/analyze_patch_vote_aggregation.py`

**Input**: Patch embeddings from a single CLIP Surgery forward pass per image.

**Method**: Test 13 pooling variants (mean, max, topk20, pmean16, otsu_mean, etc.). For each, compute:
- Standalone accuracy (patch-to-text classification only, ignoring CLIP CLS and prototypes)
- Agreement rate with CLIP
- Rescue/corrupt rates

**Output**: `outputs/patch_vote_aggregation_report.md`

**Datasets**: dtd, oxford_flowers, oxford_pets (seed 1 only)

**Key finding**: `topk20` roughly doubles standalone accuracy on oxford_pets (30% → 65%) by focusing on most relevant patches.

---

### 3.3 Validation Across Seeds

**Question**: Does the agreement signal hold up across multiple seeds?

**Script**: `scripts/validate_patch_vote_signal.py` (same as 3.1, extended to multi-seed)

**Input**: Per-sample records from seeds 1-4.

**Method**: Run the same analysis across 4 seeds. Standalone accuracy and agreement rate are seed-invariant (depend only on each image's own zero-shot CLIP logits and patch embeddings). Only write purity varies by seed.

**Output**: `outputs/patch_vote_validation_report.md`

**Datasets**: dtd, oxford_flowers, oxford_pets (4 seeds each)

## Part 4: Fusion Mechanisms

### 4.1-4.2 Mechanism Comparison and Results

**Question**: How do different fusion mechanisms perform?

**Scripts**:
- `scripts/run_experiments.sh` — ran all method/dataset/seed combinations
- `scripts/summarize_results.py` — parsed `outputs/result.txt` into per-method tables

**Grid**: 5 methods × 5 datasets × 5 seeds = 125 total runs

**Methods**:
1. PTA (baseline)
2. PatchModPTA (default ProtoAlphaFusion)
3. PatchModPTA-QGated (QualityGatedFusion)
4. PatchModPTA-MVote (MajorityVoteFusion)
5. PatchModPTA-AGate (AgreementGateFusion)

**Input**: Test-time predictions logged to `outputs/result.txt`

**Output**: `outputs/experiment_summary.md`

---

### 4.3-4.4 Delta Analysis and Fusion Collapse

**Question**: Why does always-on fusion (ProtoAlpha, QGated) collapse on fine-grained datasets?

**Script**: No dedicated script. This finding was derived from analysis of the fusion results.

**Source**: `outputs/patch_level_fusion_summary.md` (Section: "Why Always-On Fusion Collapses"), which synthesized:
- Accuracy deltas from `outputs/experiment_summary.md`
- Qualitative analysis of per-dataset patterns

**Method**: Examined how always-on fusion adds noise from independent patch predictions (~59% independence on fine-grained datasets), while gating mechanisms (MVote, AGate) silence bad predictions.

## Notes

1. **No GPU runs for post-hoc analysis**: Purity (2.1), separability (2.2), and agreement (3.1-3.3) analyses were all computed from stored records or bank dumps — no new model inference was needed.

2. **Seed invariance**: Standalone accuracy and agreement rate (3.1-3.3) are seed-invariant — they depend only on each image's own zero-shot CLIP logits and patch embeddings, not test-set processing order. Only bank-dependent metrics (write purity) vary by seed.

3. **Pre-registration**: The patch benefit study was pre-registered in `outputs/patch_benefit_prereg.md` before running experiments.

4. **Data lineage**: All experimental records are stored in `outputs/records_patch_benefit/` as JSONL files with schema defined in `.omo/plans/perclass-difficult-classes-validation.md`.
